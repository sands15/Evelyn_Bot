# 2026-08-20 Worklog

## Bounded LLM task loop

- 기존 Router → registered skill/FastAction → Main 구조 사이에 event-driven task loop를 연결했다.
  명시적 `/작업 <목표>`만 진입하며 worker는 한 번에 한 typed step을 제안하고 executor의
  관측·검증 receipt를 다음 판단에 돌려준다. 완료·실패·승인 대기·불확실·예산 소진은 서로 다른
  terminal state이고 Main은 최종 전달만 담당한다.
- 기본 상한은 6 step, 120초이며 worker 6초·tool 20초 hard timeout과 TurnScope 취소를 적용한다.
  실행됐지만 검증되지 않은 effect는 `uncertain`으로 끝내고 자동 재시도하지 않는다.
- 자동 권한은 server-attested Control Page의 bounded workspace list/search/read/exact-file diff,
  runtime status, 사용자가 명시한 public web search로 제한했다. workspace edit/test, dependency,
  service·Docker·audio·Minecraft·commit은 승인 대기이며 delete/reset, credential, push/deploy,
  external send, policy/evaluator 변경과 arbitrary shell은 loop에서 금지한다.
- Windows Host Supervisor read queue는 domain-separated HMAC, boot instance, task/grant/action/step,
  surface/tool/args hash와 TTL에 결박한다. edit/test는 queue에서 실행하지 않으며 private/runtime
  roots와 symlink/junction/reparse를 읽지 않는다.
- Fast `/작업취소 <task-id>`는 exact background action만 취소한다. Core foreground 작업은 기존
  TurnScope cancellation을 쓴다.

## Staged workspace edit approval

- `workspace_edit`는 한 task당 한 번, 한 UTF-8 file create/replace만 stage한다. Control Page는 48 KiB 이하의
  full diff와 base/candidate SHA·git status를 보여 주고, 사용자는 30초 one-use token과 dirty-base 별도
  checkbox로 exact mutation을 승인한다. public state에는 task/approval locator만 둔다.
- approval은 task/grant/action/step/tool/args hash, Host generation, target identity, base/candidate SHA와 preview
  digest에 결박된다. claim→Host apply→Bot complete 뒤 같은 coroutine이 재개되며, candidate SHA와 같은
  same-path read receipt가 있어야 완료된다. 한 번 실행된 effect, completion loss와 cleanup ambiguity는 자동
  재시도하지 않는다. 취소는 public FastAction에서도 `cancelled`로 남긴다.
- read queue와 분리된 mutation HMAC을 Control Page와 Windows Host에만 주입한다. transient stage request의
  raw edit payload는 bounded IPC 예외로 Host read 직후 unlink하고 boot/TTL purge하며 response/state/log에는
  넣지 않는다. Windows apply는 ADS를 거부하고 conditional exchange가 밀어낸 base를 검증한다. concurrent
  save나 backup cleanup이 불확실하면 `workspace_edit_recovery_required`로 닫고 성공을 반환하지 않는다.
- `workspace_test`, service/Docker/Minecraft effect와 active harness/authority/evaluator self-edit는 계속
  차단한다. test는 별도 no-network/no-secret/read-only-base sandbox가 생긴 뒤에만 연다.
