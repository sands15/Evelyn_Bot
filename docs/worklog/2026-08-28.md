### 예상 밖 결함과 처리

- **ledger·삭제 currentness:** feedback ledger가 첫 5,000개에서 잘려 stale active를 고를 수 있던 문제를
  stable generation keyset 전체 읽기로 바꿨다. generalize/eval append 직전 source 삭제 race는 exact generation
  CAS로 막고, active failure receipt를 실제 task source parent에 연결해 사용자 삭제 시 함께 제거되게 했다.
- **승격 권한:** revoke가 fresh action-bound OTP 없이 가능하던 경로, 존재하지 않는 version의 action preview가
  403 권한 경계 대신 일반 오류를 내던 경로, 이전 evaluator/contract chain을 rollback 대상으로 고르던 경로를
  현재 action/version/generation·고정 evaluator에 fail-closed로 결박했다.
- **canary lifecycle:** client가 aggregate를 제출하거나 같은 run을 재시도할 수 있던 계약을 서버 소유 exact
  10 terminal receipt로 교체했다. task 예외·finalizer 실패·restart·source 삭제 뒤 running canary가 고착되던
  문제는 raw durable running record의 conservative abort/revoke와 admission close로 닫았다. 기존 active는
  abort로 변경하지 않는다.
- **task 공개 기록:** 잘못된 completed result를 의미 검증 전에 public `taskRecord=completed`로 붙이던 false
  success를 검증 뒤 commit으로 바꿨다. 기본 guidance 없음에도 새 kwargs를 전달하던 호출 계약 drift와 구형
  voice dependency test double의 optional provider `AttributeError`도 하위 호환으로 고쳤다.
- **eval runner:** `inputCaseDigest`가 실제 입력 대신 기대 상태만 해시하던 문제, blocking hook이 실행 중 Qwen
  요청의 cancellation/deadline을 소유하지 못하던 문제, 임의 source/evaluator/tool-grant report가 gate를
  통과하던 문제를 fixed fixture digest, source-owned capacity-one adapter와 exact identity로 닫았다. Docker
  ignore가 evaluator를 production image에서 제외하던 누락도 수정했다.
- **Control Page·Discord:** rollback/revoke proxy가 guidance body를 내보낼 수 있던 projection을 content-free로
  고정했다. feedback target의 source ancestry/session close purge 누락, close와 capture commit race, 전달 실패
  답변이 최신 target이 되던 문제를 same-lock lease CAS와 delivery/playback completion fence로 닫았다.
- **전체 회귀에서 드러난 잠재 결함:** deletion journal lock guard가 자기 lock I/O뿐 아니라 호출자 본문의

  writer/read guard 양쪽에서 분리했다. workspace symlink test는 allowlist 밖 `link.txt`라 link 검사에 도달하지
  못하던 기존 모순을 허용된 `docs/link.txt` fixture로 고쳤다. P1 결선으로 `main.py`가 2,504줄이 된 구조 예산은
  의미 변경 없이 2,500줄로 복구했다. SQLite test handle, explicit purge callback wiring도 함께 닫았다.
