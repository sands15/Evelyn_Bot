- 기존 `self_preservation`을 용암·화재·익사·치명 피해의 단일 P0 소유자로 보존했다. Evelyn P1은

## Mindcraft 위험 event와 식량 recovery live 검증

  disconnect했고, 이후 고정 3초 재시도도 새 선점 loop가 됨을 source review로 확인했다.
- 수정 후 식량 recovery는 허기 14~11에서 idle-only, 10 이하에서만 선점한다. mature crop과 성체

  즉시 cooperative cleanup으로 돌아온다. 실제 hunger/안전식량/wheat 증가만 progress다.
- local source가 없으면 무작위 이동하지 않고 30초 동안 planner food search에 handoff한다.

## Mindcraft hostile 회피·종료 경계 후속

- 승인된 bounded live에서 hostile 판단 callback 진입은 `decision_to_action_ms=0`이었다. movement
  control을 idle `self_preservation`이 다음 100ms tick에 지우던 원인을 확인해 단일
  `evelynMovementOwner` lease를 존중하도록 수정했다. 이후 direct reflex가 근접 다중 위협에서
  피해 없이 안전 반경 근처까지 거리를 확보한 표본을 확인했다.
- P0 reflex 뒤 full tactic이 pathfinder로 되돌아가 추격을 다시 허용했고, 이 구간에서 피해와 사망
  표본이 발생했다. forced recovery sprint의 직선 corridor 검증, 2.5초 heading 유지, 모든 immediate
  threat의 cover 합산을 추가하고, 무장 없음·다중 적·원거리 적은 tactical flee에서도 18블록 안전
  반경까지 direct sprint를 유지하도록 수정했다. 마지막 bounded run에는 actionable hostile가 투영되지
  않아 이 최종 tactical 전환의 world effect는 live 검증하지 않았다.
- 초기 plugin 준비 전 `requestInterrupt()`가 존재하지 않는 PvP controller를 호출해 child가 종료되던
  경계를 optional stop으로 닫았다. child stdout/stderr는 PIPE로 계속 drain하되 원문은 즉시 폐기하고,
  fixed category와 exit code/signal/timestamp만 최대 12개 원자 저장한다. readiness는 spawn 이후 3초
  안정 연결과 current-generation fatal event 부재를 요구한다.
- 공식 disconnect 중 기록 flush를 기다리는 동안 추가 피해가 가능했던 순서를 고쳤다. idempotent
  shutdown은 `_disconnectHandled` fence 뒤 `bot.quit`/`bot.end`로 연결을 먼저 닫고, combat-history
  load와 writer flush 뒤 process를 종료한다. SIGKILL에서 마지막 episode 보존은 보장하지 않는다.
- 최종 image `sha256:3cc6c50504604af4bc3ff22bf3e17f4321531a68057b01f7a485f3bdcc8e50aa`는
  planner 32개와 통합 126개, 합계 Node 158개 및 patch/lint/combat/latency smoke를 통과했다.
  `.venv` Mindcraft 계약 31개, Compose config, source↔container 핵심 파일 hash, Python compile과
  scoped diff check도 통과했다. 컨테이너는 새 image로 healthy이며 bot은 running/connected/lease가
  모두 비활성이다. 최종 관측이 치명적 저체력이어서 재접속하지 않았다. 따라서 이번 결과는 빠른
  판단과 직접 회피의 부분 live 증거이지 식량 획득, 최종 tactical effect, p50/p95 또는 장기 생존
  성공 증거가 아니다.
