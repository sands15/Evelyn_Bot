# 2026-08-09 작업 기록

## Mindcraft atomic process-local safety boundary

- default history를 bounded process-local turn으로 제한하고 `load_memory=false`로
  고정했다. Compose의 `bot_memory/mindcraft` mount와 planner recovery state path를
  제거했으며 recovery persistence는 no-op이다.
- pre-existing `memory.json`, archive와 legacy log는 읽거나 현재 generation으로
  rebase하거나 삭제하지 않는다. restart restore와 user data cleanup을 구현했다고
  주장하지 않는다.
- generation exposure가 turn 첫 await 전부터 awaited final route/action sink까지 유지된다.
  inter-agent pause/classifier와 timer queue도 같은 경계를 사용한다. exposure 중 clear는
  busy로 닫히고 성공한 clear는 history/queue, recovery/action-mode, self-prompt,
  last-sender와 goal-manager의 raw execution/gate/observation 상태를 함께 초기화한다.
- goal/status artifact는 command/result/reason/argument 원문을 쓰지 않고 enum code와
  count/boolean/fixed error code만 남긴다. Node writer와 Python status owner는 legacy raw
  projection을 재사용하지 않는다.
- detached inter-agent conversation 전송과 종료된 conversation timer를 whole-turn 경계에
  결합해 clear 뒤 사후 전송·ghost turn을 막았다.
- Google translation 경로는 local identity transform으로 교체했다. Node child
  stdout/stderr는 `DEVNULL`이며 기존 log는 변경하지 않는다.
- 이번 증분은 source-level 경계다. Docker image, 실제 Minecraft login/action,
  live clear는 실행하거나 검증하지 않았다. 문서에는 private content를 기록하지 않았다.
- 검증: Mindcraft 25개, Minecraft 227개(skip 11), Voyager 24개, runtime 782개(skip 4),
  CI-equivalent 전체 3,138개(skip 22), JS 구문과 Docker patch stack 적용이 통과했다.

## 당시 남은 P1

- local/router 요청을 fixed-route authenticated Bot API broker로 모은다.
- 기존 `memory_exposure_request` lease를 Node delivery ACK까지 유지하고 assistant
  history를 strict compact receipt가 있는 structured turn으로 전달한다.
- legacy memory/archive/log cleanup이나 migration은 사용자 승인 뒤 별도로 수행한다.
- recovery의 same-command/different-target exact correlation을 content-free 방식으로 보강한다.

## Docker runtime checker fail-closed

- 실행 중 HTTP 서비스가 응답하더라도 `docker version`, `docker compose config`,
  `docker compose ps`가 실패하면 검사기가 성공을 보고하던 PowerShell native-command
  false positive를 닫았다. GPU 조회도 같은 방식으로 nonzero를 경고로 처리한다.
- 오류 원문과 host 경로는 출력하지 않고 고정 code만 표시한다. 실제 sandbox 실행에서
  Docker API 접근 거부가 3개 실패로 집계되어 최종 exit 1이 됐고, Local I/O Bridge와
  core HTTP readiness는 읽기 전용으로 별도 확인됐다. 마이크·Discord·Minecraft는
  시작하거나 변경하지 않았다.
- 검증: checker·Compose 관련 25개 통과, PowerShell 실제 실패 경로 exit 1 확인.

## 비-Minecraft 음성·Runtime Health 연속성

- voice validation GET이 terminal session을 정리한 뒤 철회 전 consent capability를
  반환하던 경합을 닫았다. session은 한 번만 읽고 현재 consent projection을 성공·
  cleanup 실패 응답의 공개 사본에 붙인다.
- Runtime Health probe마다 manifest timeout을 강제해 멈춘 probe가 전체 Control Page
  상태 수집을 무기한 막지 못하게 했다. timeout은 원문 없는 고정 reason만 남긴다.
- 실패한 Discord 내부 reconnect가 stale voice client를 listener-ready로 저장·반환하던
  경로를 actual `is_connected()` 성공 경계로 닫았다.
- 시작 시 voice 연결이 없으면 전달 전 search follow-up을 `delivery_uncertain`으로
  소모하던 경로를 닫았다. claim을 해제한 `delivery_ready`를 connected rearm 직후 다시
  복구하며, 재생 시도 뒤의 모호한 실패는 기존대로 자동 재시도하지 않는다.
- 읽기 전용 live preflight는 active validation session 없음, mic physical OFF,
  output ready, OmniVoice warmup 완료와 오류 0을 확인했다. 마이크·Discord·Minecraft와
  speaker playback은 시작하지 않았다.
- 검증: 변경 파일 집중 80개, voice 전체 610개(skip 5), Python compile과 diff check 통과.
- 추가 검증: search follow-up 22개와 Discord I/O 전체 125개 통과.

## 비-Minecraft offline reliability/privacy closure

- 삭제 tombstone과 source redaction 뒤 index/hot-context cleanup이 integrity-class
  오류를 내더라도 ledger final validation이 정상이면 applied cleanup 503을 보존한다.
  실제 ledger 손상은 기존 exact/content-free integrity 503으로 유지한다.
- Discord playback의 prior source와 `after` callback 대기를 기존
  `OMNIVOICE_TIMEOUT_SEC`(기본 180초)로 제한했다. timeout은 같은 source가 current일
  때만 정지하고 기존 failure finalizer로 전파되어 room lock과 user-only continuity를 회수한다.
- Local Bridge의 validation STT 요청에 `validation_bound`만 전달해 STT 완료 로그의
  transcript를 길이 marker로 바꿨다. validation session/attempt ID는 보내지 않는다.
- 실제 마이크·스피커·Discord·Minecraft·Docker는 시작하거나 변경하지 않았다.
- 검증: memory 전체 293개(skip 1), voice 전체 615개(skip 5), deletion HTTP/middleware
  35개, Python compile과 allowlist diff check 통과.

## Voice completion과 late-turn fence

- 취소된 `TurnScope`에 뒤늦게 붙는 current task는 즉시 거부하고 새 background
  task는 coroutine 본문 실행 전에 취소한다. 교체된 턴의 사후 발화와 memory
  write-behind가 같은 공용 경계를 우회하지 못한다.
- Discord single·streaming TTS가 `playback_completed=false`를 명시하면 비어 있지
  않은 답변도 완료로 반환하지 않고 기존 failure finalizer로 보낸다.
- Local speaker도 single 반환값과 streaming의 이 턴별 queued/played chunk 수를
  같은 완료 경계에 투영한다. 부분 재생, 다른 턴의 전역 누계, qualified interrupt와
  실패한 full-answer fallback은 성공으로 확정하지 않고 빈 답변 분류는 유지한다.
- voice ingress worker의 catch-all 로그는 exception type만 남기며 upstream 오류
  메시지·응답·경로 원문을 기록하지 않는다. 오류 뒤 다음 queue item과
  `task_done` 처리는 계속된다.
- 실제 Discord·마이크·스피커·Minecraft·Docker는 시작하거나 변경하지 않았다.
- 검증: core 전체 738개(skip 1), voice 전체 626개(skip 5), 인접 memory/UI/
  Discord 17개와 Python compile·allowlist diff check가 통과했다.

## Mindcraft broker와 Local Bridge software playback completion

- Mindcraft Node planner의 direct local/router/Codex model 호출을 제거하고 전용 token-file
  authenticated Bot API broker 하나로 모았다. 서버가 fixed upstream을 선택하고 공용
  conversation filter와 `memory_exposure_request`를 Node frame consumer의 exact
  `delivered|discarded` ACK까지 유지한다. active lease request ID는 replay TTL sweep과
  completed-window eviction에서 보존한다.
- 현재 bounded process-local turn은 core memory 입력이 없다. broker request projection은
  strict `not_used` receipt를 쓰고 다른 returned state는 거부한다. ACK는 frame
  parse/validation까지만 증명하며 generation exposure가 실제 awaited route/action sink까지
  별도로 유지된다. durable bound-receipt restart history나 legacy cleanup은 구현하지 않았다.
- TTS 재생이 필요한 Local Bridge reply는 HTTP EOF만으로 assistant history, continuity와
  background action을 확정하지 않는다. exact bridge instance·turn·assistant hash의
  authenticated `played` ACK 뒤 한 번만 commit하며, `failed|partial|cancelled`, error reply,
  bridge rotation·동시 재시작과 TTL orphan은 durable discard/no-replay로 정리한다. ACK는
  HTTP 전송에만 포함하고 signed status artifact에는 쓰지 않는다.
- 검증: continuity 87개, Mindcraft/broker/Compose 관련 56개, voice 633개(skip 5),
  CI-equivalent 전체 3,190개(skip 22), Python·JavaScript 구문과 diff check가 통과했다.
  실제 마이크·스피커·Discord·Minecraft·Docker는 시작하지 않았다.
