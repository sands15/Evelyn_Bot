## 기본 TTS OmniVoice 전환

- 실제 기본 `tts:8880`이 VoxCPM2였고 별도 host 8881만 OmniVoice였던 불일치를
  확인했다. 클라이언트 URL과 24 kHz mono PCM 계약은 유지한 채 기본 Compose 역할을
  `k2-fsa/OmniVoice`로 바꿨다. VoxCPM2는 host 8881의 opt-in 호환성·진단 서비스로
  남겼으며 자동/runtime fallback이나 기존 client reroute로 연결하지 않았다.
- 외부 OmniVoice Dockerfile의 mutable GitHub 설치와 11 GB 전체 context 전송을
  사용하지 않는다. 검토된 `omnivoice_server/` Python 20개만 named context로 복사하고
  exact 파일 목록과 SHA-256을 build에서 검증한다. 고정 revision의 필수 model snapshot
  경로 13개도 시작 시 SHA-256으로 검증한다. 직접 runtime 의존성만 고정하며 전이
  wheel과 CUDA base image digest까지 고정된 완전 재현 build로 부르지 않는다.
  voice profile과 `hub/` cache는 read-only이고 offline model revision
  `c5fdb5ccb189668d56333f77ba2629f4cd7535f4`를 요구한다.
- Compose, launcher, manifest와 runtime checker는 exact OmniVoice model identity와
  `model_revision`을 공통 readiness 계약으로 사용한다. Local 기본 합성은 sentence
  HTTP PCM streaming이며 실험적 blockwise generation은 safe disconnect cancellation
  전까지 비활성화했다. server patch는 operational log에서 text/path/session identifier를
  제거하고 profile API와 validation 오류 응답에서 입력 원문을 숨긴다.
- Compose TTS에는 `pull_policy: never`를 적용하고 path-safe builder가 missing/fresh
  image를 만들도록 했다. standalone TTS launcher도 missing image를 자동으로 builder에
  위임하며 Supervisor repair는 existing image만 사용한다.
  최종 집중 계약 149개, 기존 TTS 요청/소스/VoxCPM profile 17개와
  JSON mismatch integration 1개가 통과했고 PowerShell parser, source manifest 검증,
  `compileall`, `git diff --check`가 통과했다.
- Local Bridge 경로 변경 뒤 voice 전체 606개(skip 5)가 통과했다. 이는 실제 모델
  load나 스피커 청취가 아니라 mock/source 회귀 증거다.
- 최종 runtime 전체 756개(skip 4)도 실패 없이 통과했다. 이전 광역 실행에서 보였던
  Fast Control live-state assertion 1개는 이번 전체 재실행에서는 재현되지 않았다.
- Docker read-only Compose 검증조차 Codex 권한 승인 사용량 제한으로 거부됐다.
  따라서 새 이미지 build/recreate, `/health`, `/v1/models`, 실제 Evelyn clone-stream
  합성, privacy 응답과 Local Bridge warmup은 수행하지 않았고 live 전환으로 보고하지
  않는다.
