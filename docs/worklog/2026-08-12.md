# 2026-08-12

## `/mic on` voice-validation drawer visibility

- 실행 중 Control Page에서 `/mic on` 응답과 `voice_validation/open` panel command가
  Bot API와 public proxy까지 동일하게 전달됐지만, 브라우저 consumer가 숨은 drawer
  내부 버튼에 scroll·focus만 적용해 오른쪽 패널은 계속 화면 밖에 남는 경계를 확인했다.
- command consumer가 drawer에 idempotent `open` class를 먼저 추가한 뒤 기존 검증 시작
  버튼 scroll·focus를 수행하도록 수정했다. 마이크 ON이나 consent preview/apply는 직접
  실행하지 않아 명시적 청취 동의 경계는 그대로다.
- Node 행동 회귀는 `open -> scroll -> focus` 순서와 같은 command 재적용의 무중복을
  고정한다. UI 집중 40개와 CI-equivalent 전체 3,253개(skip 22)가 통과했다. 실행 중
  Control Page를 새로고침한 브라우저에서 drawer open, opacity 1, 검증 시작 버튼의
  화면 표시·focus를 확인했다. 마이크·스피커·Discord·Minecraft·Docker는 시작하지 않았다.

## Runtime error observability false-clear

- 실행 중 Runtime Health는 optional service 때문에 degraded였지만 오류 패널은 clear/0이었다.
  선택 서비스 OFF 자체는 예외가 아니므로 그대로 두고, 실제 Fast Control continuity 오류
  artifact가 collector와 public source allowlist에서 빠진 경계를 별도로 확인했다.
- `fastControlContinuity`를 정식 source로 추가했다. 필수 runtime service
  probe가 counter payload 없이 실패하면 `currentErrorCount`에는 반영하되 기록된 예외
  `totalCount`는 올리지 않는다. 이 합성은 Control Page·Bot API·세 LLM·TTS·STT에
  적용하며 UI도 두 숫자를 명시적으로 구분한다.
- Optional payload-less failure는 durable desired-state가 없어 의도 OFF와 예상 밖 장애를
  구분하지 못하므로 Runtime Health에만 남긴다. 현재 Python backend는 재시작하지 않아
  live 오류 API에는 아직 이전 source 목록이 보이고, 정적 UI의 새 합계 문구만 반영됐다.
- 현재 artifact에 새 collector를 read-only로 적용해 Fast Control source가 available/ready로
  잡히고 전체 source가 9개로 늘어나는 것을 확인했다. focused 40개, Runtime Health·Control
  Page 인접 159개(skip 2), CI-equivalent 전체 3,255개(skip 22), Python/JavaScript 구문과
  diff check가 통과했다. 실행 중 서비스는 재시작하지 않았다.
