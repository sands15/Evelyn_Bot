## Windows launcher startup error codes

- `start.bat` 실패가 PowerShell 원문만 잠깐 표시하고 창을 닫던 경계를 확인했다.
  background batch의 parse-time `%ERRORLEVEL%` 캡처도 실제 종료 코드를 잃을 수 있었다.
- 사용자용 `EVL-START-NNNN` namespace를 추가했다. Docker CLI·Engine·Compose를 service
  시작 전에 구분하고 source/config, Docker start, readiness, Host bridge와 미분류
  실패를 fixed code와 action으로 표시한다.
- latest startup log는 timestamp, code, exception type과 fixed stage만 기록한다.
  최상위 launcher만 실패 시 창을 유지하며 내부 자동 restart launcher에는 pause를
  추가하지 않았다. 실제 Docker service는 시작하지 않고 source/test와 dirty-tree
  early-failure 경계만 검증한다.
- user-owned `docs/99_PROJECT_INBOX.md`는 runtime source가 아니므로 dirty-tree Git
  pathspec에서 정확히 한 경로만 제외했다. 다른 tracked/untracked 변경은 계속
  `EVL-START-2001`로 fail-closed한다.
- launcher·Compose 집중 55개와 CI-equivalent 전체 3,246개(skip 22), PowerShell 구문과
  diff check가 통과했다. Docker·Discord·마이크·스피커·Minecraft service는 시작하지
  않았다.

## Local mic command and Fast Control text projection

- 실행 중 content-free 상태를 확인하니 consent는 Control Page 재시작으로 철회된
  `inactive`였고 Local Bridge는 장치 오류 없이 mic OFF였다. `/mic on`은 실제 ON을
  수행하지 않으면서 같은 동의 문구만 반복하던 명령·설명 불일치가 있었다.
- `/mic on`은 validation 전용 권한을 우회하지 않고 Control Page의 검증 시작·청취
  동의 영역을 열고 포커스한다. capture-ready와 authenticated watchdog, durable
  consent/host-lease fence가 모두 current일 때만 현재 ON으로 인정한다. panel command에
  process generation을 붙여 Bot API 재시작 뒤 작은 command ID도 열린 브라우저가
  적용하며 `/mic off` 복구 의미는 유지한다.
- 최근 Fast Control turn에는 assistant text와 playback·continuity 완료 증거가 있었지만,
  저장 기억을 요청하지 않은 빈 context receipt가 `not_requested/empty`로 모순되어
  `unattributed`로 강등됐다. 그 결과 TTS는 재생됐지만 공개 채팅 필터가 텍스트만 숨겼다.
- 빈 context 조정에서 exact `not_requested/not_requested`를 보존해 compact `not_used`로
  완료한다. 손상되거나 기억 의존성을 증명하지 못한 receipt의 fail-closed 제거 정책은
  완화하지 않았다. focused 123개, 손상 receipt 안전 회귀 63개, 관련 회귀 268개와
  CI-equivalent 전체 3,253개(skip 22)가 통과했다. 실제 마이크·스피커·
  Discord·Docker를 시작하거나 현재 서비스를 교체하지 않아 수정 후 UI는 사용자
  실사용으로 확인한다.
