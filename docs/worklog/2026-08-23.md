## Voice lease durable I/O and transition ownership

- `VoiceInputLeaseManager` load/commit을 completed-turn과 같은 shared warm killable artifact child 및
  deadline에 연결했다. pre-replace stall은 kill/reap 뒤 실패 폐쇄하고, post-replace outcome-unknown은
  canonical disk를 exact 재확인한다. unreadable canonical owner는 `blocked`로 latch해 덮어쓰지 않는다.
- Bot API manager 호출은 event loop 밖에서 실행한다. caller cancellation은 bounded worker가 끝날 때까지
  shield-drain한 뒤 재전파해 thread가 lease 임계구역보다 오래 살아남지 않게 했다.
- Local status heartbeat 전체, Local HTTP ON/OFF, 채팅 mic OFF, Discord acquire/release, retirement와
  failed-ON cleanup을 같은 event-loop transition lock으로 직렬화했다. final ON fence check 안에서 멈춘
  worker와 chat OFF를 경쟁시키는 회귀에서 OFF가 마지막 상태로 남는다. overlapping heartbeat도 status
  epoch를 섞지 않는다.
- 정식 `create_app()`을 통하지 않는 최소 aiohttp 통합 앱에는 AppKey가 없다는 전체-suite 실패 6건을
  확인했다. helper가 해당 loop에 fallback lock을 등록하도록 보완한 뒤 6건과 exact race가 모두 통과했고,
  독립 재검토에서도 공유 잠금 의미가 유지됨을 확인했다.

## STT physical worker lifetime

- caller timeout이나 cancellation 뒤 `asyncio.to_thread()` wrapper만 끝나고 실제 blocking STT thread가
  계속 실행되는 동안 shared inference lock이 풀려 후속 STT가 겹치는 race를 재현했다.
- caller는 기존 timeout/cancellation을 즉시 받고, shared lock은 physical worker가 실제 반환한 done
  callback에서만 해제한다. 늦은 worker 예외는 소비해 unobserved-task 경고를 만들지 않는다.
- timeout·cancellation 회귀를 포함한 `test_stt_task_runtime.py` 6개와 STT/voice 집중 88개가 통과했다.
  physical client가 영구 정지하면 lock도 fail-closed로 남으므로 실제 network/GPU fault는 live 공백이다.

## Accepted Main local and Control Page turns

- direct Main `local_mic` 경로가 Fast ingress를 우회하면서 accepted user turn을 durable checkpoint 전에
  LLM/TTS로 넘겨 restart에서 잃는 경로를 재현했다. Discord voice와 direct Main local mic 모두 exact
  source turn을 먼저 user-only checkpoint하고 receipt 뒤에만 owner/scope/reply work를 시작한다.
- Control Page 일반 text도 session lock 안에서 exact user-only turn을 시작하고 durable receipt를 받은 뒤에만
  TurnScope와 LLM을 시작한다. LLM 실패·취소 뒤 fresh restore는 `[system, user]`를 보존하고, 성공은 같은
  `complete_turn_id`에 assistant만 붙여 `[system, user, assistant]`가 되며 prompt에는 현재 user가 한 번만 간다.
- caller가 continuity commit 중 취소돼도 physical commit을 shield-drain하는 동안 session lock을 유지하고
  완료 뒤 원래 `CancelledError`를 재전파한다. 따라서 successor가 미완료 disk commit보다 먼저 state를
  바꾸지 않는다.
