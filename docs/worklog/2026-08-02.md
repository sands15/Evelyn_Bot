## Local capture-consent fail-closed 제어

### 확인된 변경

- consent 상태 누락·손상·symlink·invalid UTF-8·과도한 JSON 중첩과 이전 owner를
  `untrusted/revoking`으로 복구하고 exact OFF ACK 뒤에만 `inactive`를 기록한다.
- ON/OFF ACK를 revision, 일회성 action ID, Bridge instance digest, pending 명령
  부재와 실제 capture ready/stopped 상태에 묶었다.
- Bridge heartbeat는 독립 reporter bearer, exact schema와 단조 `statusSeq`를
  요구한다. 거부된 부분·손상·중복·역전·이전 instance 보고는 freshness를
  갱신하지 않는다.
- Control Page 내부 제어 bearer와 ON의 process epoch+`disableGeneration` fence를
  추가했다. OFF 뒤 늦게 도착한 과거 ON과 superseded waiter는 성공하지 않는다.
- Local Bridge는 ambient 환경값으로 캡처를 시작하지 않으며, 일반 `/mic on`은
  검증 동의 UI를 우회하지 못한다. launcher는 bearer 세대를 회전할 때 이전
  Supervisor/Bridge 세대를 먼저 정상 종료한다.
- launcher bearer는 Docker `up`과 Supervisor 생성의 최소 구간에만 주입하고,
  host preflight와 브라우저를 포함한 무관한 자식 환경에서는 제거한다.
- validation confirm/retry/abort, apply 사후 terminal 전환, 취소·예외와 monitor/
  startup 복구를 같은 consent lock과 exact OFF 경로로 직렬화했다.
- preview를 최신 1개와 발급 당시 validation 세대에 묶었다. unbound 동의는 canonical
  idle만 허용하며, idle ON 뒤 Discord-only 시작과 bound identity/state 유실도
  exact OFF로 닫는다.
- validation mutation 또는 그 fallback snapshot의 I/O 결과가 모호하면 즉시
  recovery/OFF를 수행하고 private 오류 원문 없는 고정 503을 반환한다.
- Supervisor Docker 복구는 `--no-deps`로 의존 서비스 재생성을 막고, 프로세스별
  credential allowlist를 적용했다. Bridge 전체 재시작은 exit 75를 받은 Supervisor가
  Discord token과 명시적 Codex credentials 경로만 짧은 handoff에 보존한다.

## Local capture hard-crash watchdog

### 확인된 변경

- Control Page가 startup·상태 전환과 active 중 1초마다 content-free owner/lease
  projection을 게시한다. projection은 목적 제한 HMAC, 고정 schema와 4 KiB 상한을
  사용하고 raw audio·transcript·prompt를 포함하지 않는다.
- Local Bridge는 각 status tick과 ON 전·후에 4초 freshness와 원래 owner/lease
  digest를 검사한다. 권한 상실 시 입력/admission을 폐기하고 exact mic stop을
  수행하며, stop 실패는 exit 76으로 프로세스를 종료한다.
- Supervisor는 서명된 전체 Bridge status를 현재 child PID/시작 시각, 고정 instance,
  `statusSeq` high-water, watchdog 시각과 nested/top-level physical OFF에 묶어
  검증한다. status reader는 128 KiB로 제한한다.
- launcher는 capture HMAC 키를 세대마다 회전하고 Control Page, Supervisor, Bridge에만
  전달한다. Control Page와 runtime repair가 만드는 다른 자식은 해당 키를 제거한
  환경을 받는다.

## Control Page 단일 capture owner

### 확인된 변경

- Control Page는 동의 manager 생성·상태 읽기 전에 stable
  `voice_capture_consent/owner_claim.lock`의 process-lifetime OS lock을 획득한다.
  새 잠금 구현이나 의존성을 추가하지 않고 기존 Windows byte-range/POSIX `flock`
  primitive의 stable-file, symlink, inode, backend fail-closed 검사를 재사용했다.
- busy 또는 unavailable loser는 고정 startup 오류만 내고 기존 state, heartbeat,
  recovery, revoke, mic ON/OFF를 수행하지 않는다.
- owner cleanup context가 consent context를 감싼다. 정상 종료와 cleanup 취소 모두
  monitor/heartbeat task cancel, 실제 `to_thread` writer drain, exact OFF 철회와 durable
  전환을 하나의 보호된 task로 끝낸 뒤에만 owner lock을 반납한다.
- runtime artifact retention은 사용자 지정 matching rule이 있어도
  `owner_claim.lock`을 정리 후보로 선택하지 않는다.
- hard-crash에서는 커널이 lock을 회수한다. successor는 기존 active lease를
  복구하지 않고 기존 startup recovery 계약으로 OFF부터 수행한다.

## Validation ingress의 ephemeral continuity 완료

### 확인된 변경

- validation 응답은 전용 content-free delivery binding을 사용하며, 응답 원문 대신
  SHA-256 marker와 non-replayable receipt만 ingress에 결합한다.
- 완료 시 normal session store/history를 변경하지 않고 checkpoint generation과
  ingress terminal state만 순서대로 durable advance한다.
- terminal begin 뒤 checkpoint 전·후 어느 경계에서 재시작해도 marker를 근거로
  동일 경로를 재개하며 normal history를 validation 원문으로 복원하지 않는다.
- 첫 응답 byte 전에 durable 기록한 exact validation `deliveryRef`도 recovery marker로
  사용한다. reply bind 전 crash는 entry-bound synthetic marker로 terminalize하며
  session history와 replay에는 포함하지 않는다.

### 검증

- focused happy/restart/exact-binding 4개, fast-control continuity 17개,
  continuity restart 1개, ingress recovery 26개와 API ingress integration 22개가
  통과했다.
- Python `py_compile`과 변경 파일 `git diff --check`가 통과했다.
- 실제 마이크·스피커·Discord 서비스는 시작하지 않았다.

### 남은 제약

- accepted validation user text는 기존 ingress claim FSM이 exact text/hash binding을
  요구하므로 bounded ingress journal에는 만료 전까지 남는다. 이번 변경은 이를
  checkpoint/session history나 replay 응답으로 복제하지 않는다.

## Local Voice consent generation·claim 선형화 완료

### 확인된 변경

- durable Local Voice issue/consume은 lowercase SHA-256 capture fence digest를
  필수로 받고 v2 ingress turn/reservation proof, token record와 exact revocation
  request에 결합한다. manager 재시작 또는 consent A→B 교체 뒤 A token은 B proof로
  reservation을 claim할 수 없다.
- durable reservation이 있는 token은 `reservation_verified=true`, exact reservation
  ref와 exact ingress turn receipt를 모두 요구한다. 검증 이벤트 쓰기가 durable
  claim 뒤 실패해도 type-only 로그로 흡수해 token과 LLM을 재실행하지 않는다.
- Control Page의 durable consent state 변경과 Bot API의 마지막 fence 확인+
  reservation/claim은 stable `voice_capture_consent/claim_lease.lock`의 process-local
  mutex와 OS file lock으로 직렬화된다. 철회가 먼저 선형화되면 Bot은 accepted text
  write 전에 고정 503으로 닫히고, claim이 먼저면 그 commit 뒤에 철회가 기록된다.
- Control Page writer의 claim lease 대기는 2초 단일 deadline으로 제한한다. timeout과
  state write 실패는 memory-first `revoking/untrusted`로 새 동의를 막고 physical OFF를
  계속한다. durable manager call은 cancellation-drain worker helper로 실행해 event
  loop와 app lock 순서를 보존한다.
- mic-off, consent fence 상실, restart와 shutdown은 process-local manager가 모르는
  `reserved` row도 Fast Control exact scope에서 durable purge한다. claimed/completed와
  다른 scope는 보존하고, purge 실패는 admission revocation fence와 content-free
  오류로 남긴다.
- `claim_lease.lock`은 stable 1-byte file로 유지하며 runtime retention이 삭제하지
  않는다. validation consume과 LLM generation의 예상 밖 예외·취소도 attempt lease를
  반드시 반납한다.

### 검증

- claim/revoke interleaving, manager restart, A→B proof 불일치, restart-orphan purge,
  post-claim event failure, claim-lock timeout·busy·unavailable, cancellation drain과
  physical OFF를 포함한 최종 hardening 묶음 267개가 통과했다(skip 1).
- Fast Control ingress 통합은 35개, Local Voice admission은 38개가 통과했다.

  않았다. Docker Desktop을 자동 시작하지 않았고 실제 마이크·스피커·Discord·
