  receipt의 binding을 확인한 뒤에만 token, replay ledger, follow-up lease와 count를
  확정한다.

  재시도할 수 있다.

## Local capture-consent fail-closed 제어

### 확인된 변경

- consent 상태 누락·손상·symlink·invalid UTF-8·과도한 JSON 중첩과 이전 owner를
  `untrusted/revoking`으로 복구하고 exact OFF ACK 뒤에만 `inactive`를 기록한다.
- ON/OFF ACK를 revision, 일회성 action ID, Bridge instance digest, pending 명령
  부재와 실제 capture ready/stopped 상태에 묶었다.
- Bridge heartbeat는 독립 reporter bearer, exact schema와 단조 `statusSeq`를
  요구한다. 거부된 부분·손상·중복·역전·이전 instance 보고는 freshness를
  갱신하지 않는다.
- Control Page 내부 제어 bearer와 ON의 process epoch+`disableGeneration` fence를
  추가했다. OFF 뒤 늦게 도착한 과거 ON과 superseded waiter는 성공하지 않는다.
- Local Bridge는 ambient 환경값으로 캡처를 시작하지 않으며, 일반 `/mic on`은
  검증 동의 UI를 우회하지 못한다. launcher는 bearer 세대를 회전할 때 이전
  Supervisor/Bridge 세대를 먼저 정상 종료한다.
- launcher bearer는 Docker `up`과 Supervisor 생성의 최소 구간에만 주입하고,
  host preflight와 브라우저를 포함한 무관한 자식 환경에서는 제거한다.
- validation confirm/retry/abort, apply 사후 terminal 전환, 취소·예외와 monitor/
  startup 복구를 같은 consent lock과 exact OFF 경로로 직렬화했다.
- preview를 최신 1개와 발급 당시 validation 세대에 묶었다. unbound 동의는 canonical
  idle만 허용하며, idle ON 뒤 Discord-only 시작과 bound identity/state 유실도
  exact OFF로 닫는다.
- validation mutation 또는 그 fallback snapshot의 I/O 결과가 모호하면 즉시
  recovery/OFF를 수행하고 private 오류 원문 없는 고정 503을 반환한다.
- Supervisor Docker 복구는 `--no-deps`로 의존 서비스 재생성을 막고, 프로세스별
  credential allowlist를 적용했다. Bridge 전체 재시작은 exit 75를 받은 Supervisor가
  Discord token과 명시적 Codex credentials 경로만 짧은 handoff에 보존한다.
