# 2026-08-17 Worklog

## Guild-reset delivery and autonomy linearization

- Search recovery는 시작부터 전송 종료까지 content-free guild-prefixed owner key로 추적한다.
  same-session/different-query 교체가 기존 task를 가려도 `search-drain` alias가 실제 종료까지 소유한다.
  target guild의 live search task가 있으면 reset은 marker·continuity·파일 mutation 전에 fixed
  `search_background_work_inflight`로 멈추고, 작업 종료 뒤 재시도만 진행한다.
- Discord `자율시작`은 admission guild epoch를 캡처한다. route await 뒤 grant 직전과 executor connect
  뒤 enabled/persist/task commit 직전에 open+epoch를 재검사하고, reset으로 stale하면 executor를
  disconnect하고 grant를 회수해 reset 뒤 loop나 world effect를 만들지 않는다.
- deterministic old-red는 recovery send-await 중 reset, same-session replacement drain 유실,
  route-await 중 reset, executor-connect 중 reset을 각각 고정했다. 수정 뒤 search/reset 관련 226개,
  autonomy 133개와 Discord/reset 76개, 독립 최종 감사 106개가 통과했다.
- 최신 전체 Python CI-equivalent는 3,727개 통과, 22개 skip이다. `main.py`는 2,500줄·최대 158자를
  유지한다. live Discord·마이크·Minecraft·Docker는 실행하지 않았다.

## Exact Minecraft cleanup identity

- 실행 중 world action의 exact cancel이 실패한 뒤 길드 단위 disconnect를 쓰면, 같은 guild에 새 lease가
  교체된 경쟁에서 stale cleanup이 새 세션을 정지할 수 있었다. fallback은 dispatch 때 캡처한 lease ID를
  remote payload와 owner operation-lock 내부까지 전달해 exact mismatch를 무효 동작으로 만든다.
- delegated goal 취소·응답 유실·typed-result 손상도 mutation 전 캐시된 exact lease ID가 있을 때만
  조건부 disconnect한다. ID를 모르면 다른 세션을 추측해 끊지 않고 inactive/unverified로 닫는다.
- delegated/Fast goal과 local/remote action 실행은 cached lease ID를 payload·executor 인자로 넣고 owner
  operation lock 안에서 current lease와 비교해 stale worker가 replacement lease의 goal/action을 바꾸지 못한다.
  timeout·cancel·uncertain dispatch·shutdown fallback도 같은 bound ID만 쓰며, ID 없는 손상 record는
  network cleanup 전에 실패한다.
- old-red는 generic disconnect, lease-unbound goal/action payload, executor의 사후-only lease 검사를 직접
  검출했다. 수정 뒤 전체 Minecraft 253개(skip 11), Fast Control 95개, 전체 Python 3,727개(skip 22)와
  py_compile·scoped diff-check가 통과했다. live Minecraft는 실행하지 않았다.

## Guild-scoped automatic memory reset

- automatic daily를 `daily/guild-<id>/<date>.md`로 분리하고 deterministic episode와 semantic
  episode/concept/procedure/project에 같은 opaque reset scope와 exact daily source reference를 전파했다.
  기존 shared daily처럼 block별 guild를 증명할 수 없는 artifact는 mutation 전에 fail-closed한다.
- reset은 same-scope derivation graph를 leaf-first로 tombstone한다. path/source/scope mismatch, extra 또는
  cross-guild edge, unknown legacy/local file와 late injection은 성공으로 오인하지 않는다. raw/legacy tree는
  SHA-256과 `st_dev/st_ino`를 preflight/current/unlink 직전에 결박하고 broad recursive delete를 쓰지 않는다.
  partial tombstone은 durable marker를 유지하며 repair 뒤 같은 reset 재시도로 수렴한다.
- old-red는 same-day guild7/8 혼합, nested cascade partial failure, cross-scope cascade, metadata rebind,
  identical-content directory replacement와 reset 뒤 recall을 직접 고정했다. memory 336개(skip 1), focused
  44개, reset/Discord 61개와 독립 86개가 통과했다. 실제 사용자 기억이나 live 서비스는 건드리지 않았다.

## Playback cancellation and dragon restart causality

- Discord single-source TTS는 callback 대기 중 task가 취소되면 `vc.source is source`인 경우에만
  `vc.stop()`을 호출하고 cancellation을 재전파한다. replacement source는 보존한다. 전체 voice
  748개(skip 5), reset/Discord 인접 74개와 독립 100개가 통과했다.
- `lastDragonCombatAt`은 process-local 인과 latch로 바꿔 successful nonterminal attack 뒤 child restart가
  늦은 `entityDead`를 ultimate completion으로 오인하지 않는다. verified completion은 durable하며 exact
  verified `!endGoal`만 recovery/unsafe-unarmed gate를 지나 실제 SelfPrompter를 한 번 멈춘다.
  GoalManager 42개, planner registry와 runtime contract 회귀가 통과했다. live Minecraft는 실행하지 않았다.
