  continuity 집중 60개, 실제 상태 전이 Node 표와 JavaScript 구문 검사가 통과했다.
  실제 채팅 POST나 서비스 장애 유도, 컨테이너 교체는 수행하지 않았다. bind-mounted

  ready·boot 100%를 유지했다.

## Deletion journal shared exposure lease

- 동시 memory exposure 두 개가 같은 nonblocking exclusive lock을 다투며 정상 요청도
  integrity 503이 되던 source 경계를 확인했다.
- 같은 lock file에 Windows `LockFileEx`/POSIX `LOCK_SH` shared reader를 추가했다.
  reader끼리는 process 안팎에서 공존하고 deletion writer만 배타적이며, repair는 shared
  밖의 writer에서 재검증한 뒤 reader를 다시 얻는다.
- 정상 경합은 fixed `memory_deletion_journal_busy` no-store 503으로 분리해 8798·8799와
  Control Page UI까지 보존했다. private detail/path/owner/note text는 투영하지 않는다.
- 실제 쓰기가 섞인 index sync·retrieval cache·cognitive/memory commit은 exclusive로
  유지했다. fresh write-backed recall/index/cache busy와 Sub-LLM을 최대 45초씩 감싸는
  semantic consolidation/recomposition writer, 64 MiB rotation과 운영 외부 anchor는 남는다.

## Semantic maintenance shared Sub-LLM phase

- semantic consolidation과 derivation recomposition의 함수 전체 writer를 제거했다.
  semantic은 shared reader에서 current source tombstone/full hash와 Sub-LLM 응답을
  묶고, fresh writer에서 source hash와 batch sync를 다시 확인한다.
- recomposition은 짧은 writer에서 position/revocation을 캡처하고, shared reader에서
  candidate hash와 함께 재검증한다. apply writer는 pre-sync 뒤 exact revocation entry,
  target/source hash와 ordered live/quarantine source를 다시 계산하고 post-sync까지 끝낸다.
- 실제 thread race에서 LLM 중 concurrent reader 성공과 삭제 Busy를 확인했다. handoff는
  target user-edit, direct source 삭제, target hash는 같지만 ancestor 삭제로 source가 새로
  quarantine되는 세 경우를 독립 검증했고 stale model canary는 어떤 파일에도 남지 않았다.
- memory 282개(skip 1), core 732개(skip 1), runtime 762개(skip 4), CI-equivalent 전체
  3,100개(skip 21)가 통과했다. 실제 사용자 기억과 live 서비스는 건드리지 않았다.

## Fresh recall Busy read-only fallback

- 정상 recall의 writer index sync와 retrieval cache 계약은 유지하고, writer 진입 전
  exact busy일 때만 no-repair shared reader로 전환했다. guard 진입 뒤나 종료 중 busy는
  재실행하지 않아 같은 turn을 중복 처리하지 않는다.

  `memory_version`과 필수 metadata/notes query 실패를 거부하고
  `mode=ro&immutable=1`, memory temp store로만 읽는다. cache, FTS/vector/graph rank,

- 최대 500개 후보를 현재 Markdown의 path·note ID·전체 hash, tombstone, canonical

  다시 만들며 explicit user/system note 중 `derived_from`이 없는 항목만 허용한다.
