## 한국어 ASR 목표 구조 설계

- Local Voice와 Discord의 실제 음성 경로를 각각 확인했다. Local은 완성 segment의 단일 final
  STT 뒤 durable admission으로 가며, Discord는 발화 종료 뒤 wake probe, tail partial, full,
  optional rescore를 순차 실행한다.
- 현재 STT는 Qwen3-ASR-1.7B의 stateless whole-audio POST다. Discord partial은 실시간이 아니고,
  rescore의 extra token 요청도 실제 모델 호출에 반영되지 않아 동일 greedy 추론 반복이다.
- 목표는 별도 microservice나 다중 모델 없이 기존 STT 서비스 하나를 vLLM 기반
  `start -> chunk -> finish/cancel` 세션으로 확장하는 것이다. partial은 UI·취소 가능한 prefetch에만
  쓰고 final만 기존 Local/Discord admission으로 보낸다.
- 한국어 전용 KWS는 바로 확정하지 않고 shadow 평가 뒤 도입한다. KWS는 ASR 작업을 여는 candidate일
  뿐이며, 정확한 선두 `이블린`, 45초 follow-up, 고영향 fresh-wake 규칙을 바꾸지 않는다.
- 설계, 실패·privacy 경계, SLO, 평가 corpus와 단계별 rollback은
  `docs/KOREAN_ASR_TARGET_ARCHITECTURE.md`에 기록했다. 코드·런타임 설정·외부 서비스는 변경하거나
  실행하지 않았다.

## 한국어 ASR 구현 체크포인트

- 이후 source 구현에서 stateful session은 Local Mic의 capture-time 16 kHz PCM16 경로에만 연결했다.
  Discord의 endpoint 뒤 완성 PCM은 같은 resident STT 서비스의 batch endpoint에 정확히 한 번 보내고,
  정상 non-empty final을 기존 wake와 본문 final 경로가 함께 재사용한다.
- Discord batch의 빈값·형식 오류·예외는 legacy partial/full/rescore를 다시 호출하지 않고 닫힌다.
  transport 손상 시에는 precomputed final만으로 wake를 승인하지 않고 기존 독립 wake 확인을 유지한다.
  batch 완료 뒤 listener generation/validation fence도 다시 확인하므로 stale final은 admission에 닿지 않는다.
- Bot API의 durable voice-input lease를 물리 capture의 단일 중재자로 두었다. Local Mic은 lease 획득
  뒤에만 ON을 publish하고 exact OFF ACK와 `captureStopped` 뒤에만 반납한다. Discord도 lease 획득
  뒤에만 listen하며 receive/decrypt/utterance task가 모두 멈춘 뒤 반납한다. unknown·persist/auth 실패는
  fail-closed이고, 재시작 generation·release retry·disconnect cancellation·launcher token 회전 경계도
  회귀로 고정했다.
- 전체 voice 회귀 714개 통과/5개 skip, 전체 runtime 회귀 866개 통과/4개 skip, 전체 discord_io
  회귀 143개 통과를 확인했다. 관련 Python compile, PowerShell parser, Compose config, scoped diff check도
  통과했다. 실제 Discord, 마이크, Docker image, GPU model은 시작하지 않았으므로 live 전환·latency·품질
  증거는 아니다.
